# XM 自動シグナル判定

マルチタイムフレーム（1H / 4H / 8H / 日足）のテクニカル指標から15条件を自動判定し、
**BUY / SELL / WAIT** を出力するFXシグナルダッシュボードです。

## セットアップ

```bash
npm install
npm run dev      # http://localhost:3000
```

その他のコマンド:

```bash
npm run build      # 本番ビルド
npm start          # 本番サーバー起動
npm test           # テスト（74件）
npm run typecheck  # 型チェック
```

## 構成

| ファイル | 役割 |
| --- | --- |
| `lib/technicalAnalysis.ts` | EMA / RSI / ATR / ボリンジャーバンド / MACD、ダウ理論、サポレジ、ダイバージェンス、ローソク足パターン、セッション判定 |
| `lib/autoSignalEngine.ts` | 15条件の判定とシグナル生成（`generateSignal`） |
| `lib/marketData.ts` | 相場データ取得と上位足への集約 |
| `lib/backtest.ts` | バックテストのシミュレーションと集計 |
| `lib/csv.ts` | MT4 / MT5 などのローソク足CSVの読み込み |
| `lib/tradePlan.ts` | ATRベースの損切り / 利確計算 |
| `app/api/signal/route.ts` | シグナルAPI |
| `components/` | ダッシュボードUI（チャートは外部ライブラリなしのSVG） |

## データ元

既定では **Yahoo Finance のチャートAPI**（APIキー不要）から実データを取得します。

- 1H足: 直近60日 → EMA200の計算に十分な本数を確保
- 日足: 直近2年
- 4H / 8H足: Yahooが配信していないため1H足から集約して生成

**ネットワークが遮断されている環境やAPI障害時は、決定論的な合成データに自動フォールバック**します。
その場合はUI上部に警告バナーが出て、`dataSource: "synthetic"` がAPIレスポンスに入ります。
合成データのシグナルはデモ用で、実際の相場を反映していません。

常に合成データを使いたい場合:

```bash
MARKET_DATA_PROVIDER=mock npm run dev
```

対応シンボル: USDJPY / EURUSD / GBPUSD / EURJPY / GBPJPY / AUDUSD / XAUUSD

## API

```
GET /api/signal?symbol=USDJPY
```

`generateSignal` の結果一式（`signal` / `confidence` / `conditions` / `analysis` / `chartData`）に加えて、
`tradePlan`（エントリー・損切り・利確）、`dataSource`、`candleCounts` を返します。

## バックテスト

```bash
npm run backtest -- --symbol USDJPY
npm run backtest -- --symbol USDJPY --sweep buyRsiMax=60,65,70,75,80
npm run backtest -- --csv-1h data/usdjpy_1h.csv --csv-daily data/usdjpy_1d.csv
```

1H足を1本ずつ前進させながら `generateSignal` を呼び、BUY / SELL が出たらATRベースの
損切り・利確に到達するまで先の足でシミュレートします。トレード数・勝率・損益（pips）・
プロフィットファクター・期待値・最大ドローダウンをBUY / SELL別に出力します。

**先読み（lookahead）を避けるための約束事:**

- 判定に渡すのは評価中の足までのウィンドウのみ
- 日足はその時点で確定済みのものだけ渡す（形成中の日足の終値は使わない）
- エントリーはシグナルが出た足の終値ではなく**次の足の始値**で約定
- 同じ足の中で利確・損切りの両方に触れた場合は**損切りを優先**（悲観側に倒す）
- 同時に保有するポジションは1つまで

この決済ロジックは結果を大きく左右するので、`tests/backtest.test.ts` で
約定価格・pips換算・スプレッド控除・同一足で両側に触れた場合の扱いを固定しています。

### 主なオプション

| オプション | 既定値 | 内容 |
| --- | --- | --- |
| `--symbol` | `USDJPY` | 対象シンボル |
| `--csv-1h` / `--csv-daily` | なし | 手元のCSVを使う（両方必須） |
| `--range` | `730d` | Yahooから取得する1H足の期間（最大730d） |
| `--spread` | `1.0` | 往復コスト（pips）。全トレードから差し引く |
| `--atr-stop` | `1.5` | 損切り幅 = ATR × この倍率 |
| `--rr` | `2` | 利確幅 = 損切り幅 × この倍率 |
| `--max-holding` | `120` | 決済されない場合に打ち切る足数 |
| `--window` | `1000` | 判定に渡す1H足の本数（本番アプリの取得本数に合わせる） |
| `--sweep` | なし | 閾値を振って比較（例 `buyScoreMin=0.6,0.65,0.7`） |

`--sweep` で振れるのは `buyScoreMin` / `sellScoreMin` / `buyRsiMax` / `sellRsiMin` の4つです。
既定値は `DEFAULT_THRESHOLDS`（`lib/autoSignalEngine.ts`）にあり、指定しなければ従来どおりの
挙動になります。

### CSVの形式

MT4 / MT5 のエクスポートをそのまま読めます。判別は自動です。

- 区切り文字: カンマ / タブ / セミコロン
- ヘッダ: `<DATE>` のような山括弧付き、`timestamp` `datetime` などの別名、ヘッダ無しも可
- 日付と時刻: 別列（MT5の `<DATE>` + `<TIME>`）でも1列にまとまっていても可
- 日付区切り: `2024.01.15` `2024/01/15` `2024-01-15`、エポック秒/ミリ秒も可

MT5からの出し方: チャートを開いて `F2`（気配値 → 銘柄 → バー）でエクスポート、
または「ファイル」→「データフォルダを開く」から `history` を書き出します。
1H足と日足の両方が必要です。

**タイムゾーンに注意。** 時刻にタイムゾーン表記が無い場合はUTCとして扱います。
MT5のサーバー時刻は多くがEET（UTC+2、夏時間はUTC+3）なので、そのまま渡すと
セッション判定（ロンドン / ニューヨーク）が2〜3時間ずれます。ずれたまま流すと
セッションフィルターの効き方が変わるので、事前にUTCへ直してください。

読み込み時に、同じ時刻の重複・時間の飛び・高値安値の矛盾を点検して報告します。

必要な本数は1H足が1000本以上（EMA200のウォームアップ）、日足が210本以上です。

### 実データについて

`--csv-*` を指定しない場合はYahoo Financeから取得します。ネットワークが使えない環境では
合成データにフォールバックしますが、**合成データはランダムウォークなので再現可能な
優位性が存在せず、出てくる数値は基盤の動作確認にしかなりません。**
戦略の評価には必ず実データを使ってください（実行時にも警告が出ます）。

## 判定ロジックの概要

条件は4カテゴリ・計15項目で、それぞれ重み1〜5を持ちます。

- **トレンド確認** — 1Hトレンド、MTF整合性（重み5）、ダウ理論構造
- **エントリー条件** — 20EMA方向、押し目/戻り目（重み4）、サポレジ（重み4）
- **確認シグナル** — RSI、ダイバージェンス、反転ローソク足（重み4）、ボリンジャーバンド、MACD
- **フィルター** — ボラティリティ、時間帯、経済指標、スプレッド

シグナル確定までに、さらに次のフィルターを通します。

1. コア条件（1Hトレンド + MTF整合性）と経済指標フィルターが必須
2. MTFフィルター — 4H MACDの向きと8Hトレンドが方向と一致すること
3. セッションフィルター — ロンドン（JST 16-21時）またはNY（JST 21-翌2時）のみ
4. BUYは重み付きスコア65%以上、SELLは独立スコアリング（`calculateSellScoreA`）で65%以上
5. 過熱 / 過売りフィルター（ボリンジャーバンド、MACDクロス、RSI）

## 既知の制約

- **経済指標フィルターは推定です。** リアルタイムの経済カレンダーAPIには接続しておらず、
  主要指標の定例発表時刻（JST 21:30 / 03:00 / 12:00 / 22:00）の前後30分を危険時間帯として
  一律にマークしています。実際の発表スケジュールとはズレます。
- **スプレッド判定はサニティチェックのみです。** ブローカーのbid/ask配信がないため、
  `isSpreadNormal` は価格が有効な数値かどうかしか見ていません。実運用ではブローカーAPIの
  実スプレッドに差し替えてください。
- **4H / 8H足は1H足から合成しています。** 区切りはUTCの絶対時刻に揃えてあるので取得
  タイミングでブレませんが、週末をまたぐバケットは本数が欠けるため、ブローカー配信の
  4H / 8H足とは完全には一致しません。
  なお `generateSignal` は8H足を省略すると内部で1H足を先頭から8本ずつ数えて集約します。
  この方式は取得ウィンドウがずれると区切りもずれるため、本アプリでは常に
  `lib/marketData.ts` の `aggregate` で作った8H足を明示的に渡しています。
- 表示している `confidence` は条件の重み付き充足率がベースなので、
  WAIT のときも数値が高く出ることがあります（「エントリーすべき確度」ではありません）。
- **シグナルの発火頻度は低めです。** 多段フィルターを通すため、1H足9000本
  （約1年分）のバックテストで成立するトレードは50件程度でした。
  BUY / SELL が発火しなくなる変更に気づけるよう、`tests/signalReachability.test.ts` で
  実際に発火する相場をシード固定して回帰テストにしています。

  なお `RSI >= 70 → WAIT` フィルターの効き方は、検証に使う値動きの性質に強く依存します。
  ドリフトが一定のランダムウォークではRSIが高止まりするためBUY候補の大半を落としますが、
  一定間隔でトレンドが転換するより現実的な値動きでバックテストすると、
  このフィルターを外して（`buyRsiMax=100`）もトレードは47件から50件（BUYは21件から24件）に
  増えるだけでした。閾値を調整する際は必ず実データで確認してください。

## 判定式の修正履歴

ランダムウォークで条件ごとの成立率を計測したところ、2つの条件の判定式が後段のOR節に
吸収されて意図が消えていたため修正しました。

**ダイバージェンス条件** は `divergence !== "none"` に潰れており、上昇トレンド中の
ベアリッシュ・ダイバージェンスでも成立していました。計測では成立532件のうち529件
（99.4%）がトレンドと逆向きで、シグナルに不利な材料が重み2の加点になっていました。

ただし単純に順張り一致（上昇トレンド＋ブリッシュ）だけを成立条件にすると、今度は
条件が死にます。ダイバージェンスは本質的に反転指標で、トレンドと同じ向きのものは
相場付きによらず0.2〜0.7%しか出現しないためです（定常トレンド / 120本ごとの転換 /
40本ごとの転換の3パターンで計測）。そこで **「トレンドに逆行するダイバージェンスが
出ていないこと」を成立条件** としました。成立率は56.7%で、逆行ケースは正しく不成立に
なります。

**ダウ理論構造の条件** も `marketStructure !== "RANGE"` に潰れていたため、
トレンドと構造が一致する場合のみ成立するようにしました（成立率 82.8% → 77.9%）。
こちらは順張り一致が十分な頻度で出るため、そのまま厳格化しています。

この2つは判定式にOR節を足すと再び潰れやすいので、`tests/autoSignalEngine.test.ts` に
「逆行している材料が成立扱いになっていないこと」を多数の相場で確認する性質テストを
入れてあります。逆行ケースを実際に観測できていることも同時に検証しているので、
テストが空振りすることはありません。

### スコアの下駄

フィルター4条件（ボラティリティ / 時間帯 / 経済指標 / スプレッド）は計測上ほぼ常に
成立するため、重み41点中7点が実質固定で乗っています。特にスプレッド判定は実配信が
ないため常に成立します。BUYの閾値65%を調整する際はこの下駄を考慮してください。
